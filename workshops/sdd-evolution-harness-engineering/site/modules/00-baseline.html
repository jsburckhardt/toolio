Module 0 · Core

Baseline

⏱ 10 min Pair: driver + navigator No setup beyond clone

Goal: feel the floor before we add lego on top. You can’t appreciate what RPIV gives you until you’ve felt the chaos it replaces.

What you’ll learn

  • The unit of work a # hashtag prompt actually drives.
  • How many decisions an unconstrained agent silently makes for you.
  • Why “build me a CLI” produces slop.

Concept

Before there were agents, there was autocomplete. You typed # add a function that… and the model filled in the next few lines. The unit of work was a line, sometimes a function, almost never a system.

Today’s agents can write whole modules from a sentence — but if you don’t tell them the constraints, every guess drifts. The model picks a framework. A test runner. A file layout. A naming convention. Each guess is locally plausible and globally incoherent.

This module makes you feel that drift, so the rest of the workshop has somewhere to land.

Exercise 0.1

The # hashtag flow

Open any source file in your repo. Type a # comment describing a small change. Let autocomplete run.

# add a CLI flag --dry-run that prints planned changes and exits 0

Stop after 5 minutes. Don’t fix what came out. Just look at it with your pair.

What you should see

Probably a single function with the flag added, or a copy-paste of part of your file with one new if branch. Maybe a test if you got lucky.

Debrief in pairs

  • What was the unit of work? One line? One function? One file?
  • What did the model assume that you didn’t tell it?
  • Where did the wheels start coming off?
Exercise 0.2

Scale the same prompt up

Now ask your agent the same flavour of question, but at system scale:

# Prompt your agent (Claude, Copilot, OpenCode, whatever):
“Build a CLI that supports --dry-run, --verbose, and --config, with tests.”

Do not constrain it. Don’t pick the framework. Don’t tell it the test runner. Don’t suggest a file layout. Just ship the prompt and watch.

Don’t fix the slop

You’ll be tempted. Resist. The slop is the lesson. Count the decisions the agent made on your behalf:

  • Which language? Which version?
  • Which CLI framework (click? argparse? cobra? oclif? commander?)
  • Which config format (yaml? toml? json? env vars?)
  • Which test runner? Which assertion style?
  • What is “dry-run” actually supposed to print?
  • What does --verbose mean — log level? structured output? both?

Debrief

  • How many of those decisions match how the rest of your codebase is built?
  • How many of those decisions would survive code review?
  • Which decision would have been easy for you to give the agent, if you’d known it would invent one?

Takeaway

The model is just guessing what comes next. Without constraints, every guess drifts. Prompt engineering isn’t magic incantations — it’s telling the agent the constraints, because if you don’t, it will invent them.

The rest of the workshop is about where those constraints live, and who writes them.
