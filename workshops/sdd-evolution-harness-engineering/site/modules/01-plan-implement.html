Module 1 · Core

Plan / Implement

⏱ 20 min Pair: swap roles from M0 Requires: GitHub issue #42

Goal: make planning a first-class artifact, not a paragraph in chat.

What you’ll learn

  • Work starts from a GitHub Issue. No issue, no workitem.
  • Artifacts live in project/issues/<N>/. Each issue gets its own folder.
  • A plan you can hand to an agent constrains drift in a way a chat paragraph can’t.

Concept

In Module 0 the agent invented everything because you told it nothing. Plan/Implement is the first lego brick that fixes that: before you ask the agent to write code, you write the plan. The plan is a file on disk, not a sentence in chat.

Two rules from the base repo:

  1. No issue, no workitem. If you can’t link to a GitHub Issue, you don’t have a workitem yet — you have an idea.
  2. Artifacts live next to the issue. project/issues/42/plan.md is the canonical location for the plan for issue #42. The agent reads from there. The reviewer reads from there. Future-you reads from there.
Exercise 1.1

Write the plan, then build to it

For your issue (gh issue view 42), create the workitem folder and a plan template:

mkdir -p project/issues/42
$EDITOR project/issues/42/plan.md

Steal this template, adjust to taste:

# WI-42 — <one-line summary>

## Where I am
<current state of the code, in 3 sentences>

## Where I want to go
<the acceptance criteria from the issue, restated in your words>

## How
<bullet list of concrete steps>

## What I won’t do
<scope boundaries — what’s explicitly out>

Now feed only the plan to the agent and say:

“Implement this.”

Don’t paste the issue. Don’t paste the code. Just the plan.

What you should see

The agent produces code that lines up with the steps in your “How” section, and refuses (or just doesn’t do) the things in “What I won’t do”.

If it invents a step that wasn’t in your plan, your plan was too vague.

Debrief

  • How much did the plan constrain the drift compared to Exercise 0.2?
  • Where did the plan still leave room for the agent to invent?
  • What would you have to add to the plan to remove that room?
Exercise 1.2

Loop it

Run the plan/implement cycle twice. After the first implement, write a new plan for the next slice of the same issue.

Notice that the second plan is much cheaper to write than the first — the first one nailed the conventions, and the second one inherits them.

Debrief

  • Which sections of the second plan shrank? Why?
  • If you handed your two plans to a fresh colleague tomorrow, could they continue the work? What’s missing?

Takeaway

Prompt engineering isn’t magic incantations. It’s tell the agent the constraints or it will invent them. The plan file is the constraint surface. The agent reads it. The reviewer reads it. The next workitem reuses it.

But Plan/Implement on its own doesn’t scale. The minute you build a second endpoint, you discover the plan was missing context that already existed in the repo. That’s what Module 2 fixes.
