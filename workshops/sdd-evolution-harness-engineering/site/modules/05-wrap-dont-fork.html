Module 5 · Stretch

Wrap, don’t fork

⏱ 25 min Stretch — skip in 90-min slot Requires: an upstream agent (real or simulated)

Goal: an upstream agent (HVE Core, Copilot Workspace, anything) doesn’t write artifacts where your repo wants them. Don’t fork. Wrap.

What you’ll learn

  • Why forking an upstream agent to “fit our paths” is the wrong instinct.
  • How to declare a canonical-vs-ephemeral path contract.
  • How to write a tiny safety-net script that enforces the contract before PR.

Concept

You adopt an upstream agent (HVE Core, Copilot Workspace, Cursor’s background agent, whatever). It works! Except it dumps everything into .copilot-tracking/ (or some other path it picked), which your repo wants gitignored.

Tempting move: fork the upstream agent and change the path. Don’t.

What changes when you adopt upstream agents is not the agents. It’s the team-governed operating model around them. The contract sits on your side, not theirs.

Setup (simulated upstream)

For this exercise, simulate an upstream agent: pretend yours is configured to write everything to .copilot-tracking/ (ephemeral, gitignored). Your repo requires committed artifacts under project/issues/<N>/.

Exercise 5.1

Build the contract

Add an ARTIFACT_PATHS section to AGENTS.md:

## ARTIFACT_PATHS

| Stage     | Canonical                              | Ephemeral OK in    |
|-----------|----------------------------------------|--------------------|
| research  | project/issues/<N>/research.md       | .copilot-tracking/ |
| plan      | project/issues/<N>/plan.md           | .copilot-tracking/ |
| implement | (code + tests, in their normal homes)  | n/a                |
| verify    | project/issues/<N>/verify.md         | .copilot-tracking/ |

If an artifact lands in `.copilot-tracking/`, the `promote-ephemeral` step
copies it to its canonical path before PR.

You’ve just declared the contract. The upstream agent doesn’t need to know. Your team does.

Exercise 5.2

Write the safety net

Write a promote-ephemeral script (~15 lines of bash or Python) that:

  1. Finds the latest WI folder.
  2. Copies anything in .copilot-tracking/<wi-folder>/ to project/issues/<N>/.
  3. Fails loud if a file is still in .copilot-tracking/ after PR open.

Sketch:

#!/usr/bin/env bash
set -euo pipefail

WI_DIR="$(ls -dt project/issues/*/ | head -1)"
WI_NUM="$(basename "${WI_DIR%/}")"
SRC=".copilot-tracking/${WI_NUM}"

[ -d "$SRC" ] || { echo "nothing to promote"; exit 0; }

cp -r "$SRC"/* "$WI_DIR"/
rm -rf "$SRC"

if [ -n "$(ls -A .copilot-tracking 2>/dev/null)" ]; then
  echo "ERROR: ephemeral artifacts remain in .copilot-tracking/" >&2
  ls -la .copilot-tracking/
  exit 1
fi

Run it as a pre-commit hook, a CI gate, or both.

What you should see

If your upstream agent leaves a stray file behind, the gate fails loudly — with the path of the file — before the PR is opened. The team doesn’t need to remember the rule. The harness enforces it.

Debrief

  • What would have to change if you switched to a different upstream agent next month?
  • If your team has three upstream agents (one per pod), how many wrappers do you need?
  • Who owns the wrapper — the platform team, or the team using the upstream agent?

Takeaway

What changes when you adopt upstream agents is not the agents. It’s the team-governed operating model around them.

Forking sounds tempting because it’s “just one PR upstream”. It isn’t. It’s a permanent maintenance bill, a divergent feature set, and a security review surface every time upstream ships. Wrap.
